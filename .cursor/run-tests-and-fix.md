# 运行测试并修复失败

请执行以下步骤来运行测试并修复所有失败的测试。

## 1. 运行所有测试

### 单元测试

```bash
# Python 项目
pytest tests/ -v

# Node.js 项目
npm test

# 带覆盖率
pytest tests/ --cov=. --cov-report=html
```

### 集成测试

```bash
# 运行集成测试
pytest tests/integration/ -v

# 运行端到端测试
pytest tests/e2e/ -v
```

### 记录失败

- 记录所有失败的测试名称
- 保存完整的错误输出
- 截图或录制失败场景（如果适用）

## 2. 分析失败原因

### 查看错误日志

- 仔细阅读错误消息
- 查看堆栈跟踪
- 检查相关代码

### 识别根本原因

- 是代码逻辑错误？
- 是测试本身的问题？
- 是环境配置问题？
- 是依赖版本冲突？

### 确定影响范围

- 影响多少个测试？
- 是否影响核心功能？
- 是否有副作用？

## 3. 修复问题

### 修复代码

- 实现正确的逻辑
- 处理边界情况
- 添加错误处理
- 遵循最佳实践

### 修复测试

- 更新测试断言
- 修复测试数据
- 调整测试环境
- 更新 mock 对象

### 代码质量

- 确保代码可读性
- 添加必要的注释
- 遵循编码规范
- 不引入新问题

## 4. 验证修复

### 重新运行失败的测试

```bash
# 运行特定测试
pytest tests/test_specific.py::test_function -v

# 运行失败的测试
pytest --lf -v  # last-failed
```

### 确保所有测试通过

```bash
# 运行完整测试套件
pytest tests/ -v

# 检查覆盖率
pytest tests/ --cov=. --cov-report=term-missing
```

### 检查副作用

- 运行相关测试
- 验证依赖功能
- 检查性能影响

## 5. 更新文档

### 代码注释

- 添加必要的代码注释
- 解释复杂的逻辑
- 记录重要的决策

### 测试文档

- 更新测试说明
- 记录测试场景
- 添加示例数据

### 项目文档

- 更新 README（如果需要）
- 更新 API 文档
- 更新变更日志

## 6. 提交更改

### Git 提交

```bash
# 添加更改
git add .

# 提交（使用 Conventional Commits）
git commit -m "fix: 修复测试失败问题"

# 推送
git push
```

### 提交消息格式

- 使用清晰的提交消息
- 引用相关 Issue
- 说明修复内容

## 📊 测试报告

请提供以下信息：

### 测试执行摘要

- 总测试数：X
- 通过：X
- 失败：X
- 跳过：X
- 覆盖率：X%

### 失败测试详情

对每个失败的测试，提供：

1. 测试名称和位置
2. 失败原因
3. 错误消息
4. 修复方案

### 修复摘要

- 修复的问题数量
- 主要更改
- 影响范围
- 测试结果

### 遗留问题

- 未解决的问题
- 需要进一步调查的问题
- 技术债务

请报告完整的测试结果和修复过程，包括所有重要的细节。
