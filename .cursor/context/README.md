# 项目上下文文档目录

本目录存放项目的背景信息和上下文文档，帮助 AI 更好地理解项目。

## 📋 目录说明

### 推荐创建的文档

1. **project-overview.md** - 项目概览
   - 项目目标和愿景
   - 核心功能
   - 技术栈
   - 团队结构

2. **architecture.md** - 架构文档
   - 系统架构图
   - 模块划分
   - 数据流
   - 接口设计

3. **coding-standards.md** - 编码规范
   - 命名约定
   - 代码风格
   - 注释规范
   - 最佳实践

4. **api-conventions.md** - API 约定
   - RESTful 规范
   - 请求/响应格式
   - 错误码定义
   - 认证机制

5. **database-schema.md** - 数据库设计
   - 表结构
   - 关系图
   - 索引策略
   - 数据迁移

6. **deployment.md** - 部署说明
   - 环境配置
   - 部署流程
   - 监控和日志
   - 故障排查

## 🎯 使用场景

### 场景 1: 新功能开发

在开发新功能前，让 AI 阅读相关上下文：

```text
@context/architecture.md @context/api-conventions.md
请根据项目架构和 API 约定，帮我设计用户认证功能
```

### 场景 2: 代码审查

在审查代码时，参考编码规范：

```text
@context/coding-standards.md
请审查以下代码是否符合项目规范
[代码]
```

### 场景 3: 问题排查

在排查问题时，参考架构文档：

```text
@context/architecture.md @context/database-schema.md
用户登录失败，可能是哪个模块的问题？
```

## 📝 文档编写建议

### 1. 保持简洁

- 只包含必要的信息
- 使用图表和示例
- 避免冗长的描述

### 2. 及时更新

- 架构变更时更新文档
- 定期审查文档准确性
- 标注文档更新日期

### 3. 结构化

- 使用清晰的标题层级
- 添加目录和链接
- 分类组织内容

### 4. 可搜索

- 使用关键词
- 添加标签
- 包含常见问题

## 🔧 最佳实践

### 文档模板

每个上下文文档应包含：

```markdown
# 文档标题

**最后更新**: 2025-11-02
**维护者**: 团队名称

## 概述

简短描述文档内容

## 详细内容

[具体内容]

## 相关文档

- [相关文档1](链接)
- [相关文档2](链接)

## 变更历史

- 2025-11-02: 初始版本
```

### 与 AI 交互

使用 `@context/` 引用上下文文档：

```text
@context/project-overview.md
请介绍一下这个项目
```

### 版本控制

- 将上下文文档纳入 Git 版本控制
- 在 PR 中更新相关文档
- 使用 Git 历史追踪变更

## 📚 示例文档

### project-overview.md 示例

```markdown
# 新闻采集系统 - 项目概览

**最后更新**: 2025-11-02

## 项目目标

构建一个自动化的新闻采集和处理系统，使用 Firecrawl API 抓取新闻内容。

## 核心功能

1. 新闻源管理
2. 自动采集调度
3. 内容处理和存储
4. RESTful API 接口

## 技术栈

- 后端: Python 3.11 + FastAPI
- 数据库: PostgreSQL
- 缓存: Redis
- 任务队列: Celery
- API: Firecrawl

## 团队结构

- 后端开发: 2人
- 前端开发: 1人
- 运维: 1人
```

## ⚠️ 注意事项

- 不要在上下文文档中包含敏感信息
- 避免文档过于详细，保持高层次视角
- 定期清理过时的文档
- 确保文档与代码保持同步

## 🚀 快速开始

1. 创建 `project-overview.md` 描述项目概况
2. 创建 `architecture.md` 说明系统架构
3. 创建 `coding-standards.md` 定义编码规范
4. 在开发时使用 `@context/` 引用这些文档
