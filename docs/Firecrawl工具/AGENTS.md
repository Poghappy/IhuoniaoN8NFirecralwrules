## 🎯 核心原则

### 1. 基于源码分析
- 所有结论必须来自真实代码文件
- 禁止基于猜想、推测或经验给出答案
- 找不到答案时明确告知"暂无结果"
- 不得提供修改官方源码的建议

### 2. 代码质量优先
- **可读性**: 代码结构清晰，命名规范，注释充分
- **可维护性**: 遵循 SOLID 原则，避免过度设计
- **安全性**: 严格处理敏感信息，遵循安全最佳实践
- **性能**: 考虑性能影响，避免不必要的资源消耗

### 3. 文档驱动开发
- 重要功能必须有相应的文档说明
- API 接口必须提供完整的接口文档
- 配置说明必须清晰
- 必须提供问题诊断和解决方案

### 4. 语言要求
- **统一语言**: 所有回复、解释、代码注释和技术说明使用简体中文
- **代码格式**: 代码本身保持原有格式，但相关解释和注释使用中文
- **沟通方式**: 保持简洁明了的表达，重点突出关键信息

## 🛠️ 开发规范

### "不重复造轮子"原则

#### 解决方案调研流程
1. **优先搜索**: GitHub 等开源平台进行全面搜索
2. **评估维度**:
   - 功能匹配度评估
   - 技术栈兼容性分析
   - 性能指标对比
   - 社区活跃度调研（Star ≥ 100，近 6 个月活跃）
   - 维护状态评估（Issue 响应 < 7 天，PR 合并率 > 60%）

#### 决策标准
- **采用现有方案**: 功能匹配度 ≥ 80%，质量评估 ≥ 4.0/5.0
- **自行开发**: 功能匹配度 < 60%，集成成本 > 自研成本

### 代码结构规范

```
项目根目录/
├── src/                    # 源代码目录
├── docs/                   # 文档目录
├── scripts/                # 脚本文件
├── .cursor/                # Cursor 配置目录
│   └── rules/              # 规则文件
└── README.md              # 项目说明
```

### 命名规范
- **文件命名**: kebab-case (user-management.js)
- **变量命名**: camelCase (userName, apiKey)
- **常量命名**: UPPER_SNAKE_CASE (API_BASE_URL)
- **类命名**: PascalCase (UserManager, ApiClient)

## 🔧 MCP 工具使用规范

### 核心原则
- **MCP 优先原则**: 所有外部工具操作必须通过 MCP 接口执行
- **工具适配原则**: 根据任务特性选择最适合的 MCP 工具
- **配置验证原则**: 执行前必须验证 MCP 工具配置状态
- **故障处理原则**: MCP 工具故障时必须完整解决后再继续任务

### 工具分类与优先级

#### 浏览器自动化类
- **优先级**: playwright > puppeteer > selenium-based
- **适用场景**: 网页操作、UI 测试、表单填写、页面截图

#### 网页抓取类
- **优先级**: firecrawl > scrapy-based > requests-based
- **适用场景**: 内容提取、数据抓取、文档处理、API 调用

#### 容器管理类
- **优先级**: Docker MCP > kubernetes-mcp > podman-mcp
- **适用场景**: 容器创建、启动、停止、删除、镜像管理

### 故障处理流程
1. **问题诊断**: 全面扫描系统状态，记录详细错误日志
2. **解决方案**: 优先调用 context7 MCP，查阅官方最新文档
3. **执行要求**: 必须彻底解决问题，禁止跳过故障

## 🔒 安全规范

### 敏感信息处理
- **高敏感**: API 密钥、数据库密码、用户隐私数据 → 必须加密存储，使用环境变量
- **中敏感**: 配置信息、业务数据、日志信息 → 访问控制，定期审计
- **低敏感**: 公开文档、系统状态信息 → 基础访问控制

### API 安全要求
- 所有 API 调用必须使用 HTTPS
- 使用安全的密钥生成和验证机制
- 实施基于角色的访问控制 (RBAC)
- 记录所有安全相关操作

## 📋 执行标准

### 任务执行流程
1. **需求分析**: 明确任务目标和约束条件
2. **方案设计**: 基于规则制定执行方案
3. **实施执行**: 严格按照规范执行任务
4. **质量验证**: 验证结果是否符合要求
5. **文档记录**: 记录执行过程和结果

### 错误处理标准
- **错误识别**: 及时识别和报告错误
- **错误分类**: 按照严重程度分类处理
- **错误修复**: 提供明确的修复方案
- **预防措施**: 制定预防类似错误的措施

## 🌍 语言要求

### 语言匹配原则
1. **优先级 1**: 匹配用户输入的语言
2. **优先级 2**: 检查自定义指令中的语言要求
3. **优先级 3**: 默认使用中文（用户 IDE 界面语言）
