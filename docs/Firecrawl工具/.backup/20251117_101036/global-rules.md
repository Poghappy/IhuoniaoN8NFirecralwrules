## 🎯 核心原则

### 1. 基于源码分析原则
- **必须遵循**：所有结论必须来自真实代码文件
- **严格禁止**：不得基于猜想、推测或经验给出答案
- **找不到答案时**：明确告知"暂无结果"，不得编造信息
- **代码修改建议**：不得提供修改官方源码的建议

### 2. 代码质量优先原则
- **可读性**：代码结构清晰，命名规范，注释充分
- **可维护性**：遵循SOLID原则，避免过度设计
- **安全性**：严格处理敏感信息，遵循安全最佳实践
- **性能**：考虑性能影响，避免不必要的资源消耗

### 3. 文档驱动开发原则
- **重要功能**：必须有相应的文档说明
- **API接口**：必须提供完整的接口文档
- **配置说明**：必须有清晰的配置指南
- **故障排除**：必须提供问题诊断和解决方案

## 🔧 MCP工具使用规范

### 核心原则
- **MCP优先原则**：所有外部工具操作必须通过MCP接口执行
- **工具适配原则**：根据任务特性选择最适合的MCP工具
- **配置验证原则**：执行前必须验证MCP工具配置状态
- **故障处理原则**：MCP工具故障时必须完整解决后再继续任务

### 工具分类与优先级

#### 1. 浏览器自动化类
```yaml
优先级排序: playwright > puppeteer > selenium-based
适用场景: 网页操作、UI测试、表单填写、页面截图
技术要求: 支持现代浏览器API、具备稳定性保证
```

#### 2. 网页抓取类
```yaml
优先级排序: firecrawl > scrapy-based > requests-based
适用场景: 内容提取、数据抓取、文档处理、API调用
技术要求: 支持多种数据格式、具备反爬虫能力
```

#### 3. 容器管理类
```yaml
优先级排序: Docker MCP > kubernetes-mcp > podman-mcp
适用场景: 容器创建、启动、停止、删除、镜像管理
技术要求: 支持完整Docker API、具备安全隔离
```

### 故障处理流程

#### 1. 自动决策流程
```yaml
系统评估:
  - 自动评估任务需求
  - 判断是否需要启用sequentialthinking MCP
  - 根据任务复杂度选择最优MCP工具
```

#### 2. 故障处理优先级
```yaml
处理步骤:
  a) 执行完整问题诊断:
     - 全面扫描系统状态
     - 记录详细错误日志
     - 分析错误根源
  
  b) 解决方案优先级:
     - 优先调用context7 MCP
     - 通过浏览器/fetch查阅官方最新文档
     - 严格按官方说明进行配置修复
```

#### 3. 执行要求
- **彻底解决**：必须彻底解决问题后方可继续任务
- **禁止规避**：禁止跳过故障或改用其他MCP工具规避问题
- **操作文档**：每个操作步骤需附带清晰的操作说明文档
- **可追溯性**：确保所有修复操作可追溯、可验证

## 🔒 安全规范

### 1. 敏感信息处理
```yaml
分类标准:
  - 高敏感: API密钥、数据库密码、用户隐私数据
  - 中敏感: 配置信息、业务数据、日志信息
  - 低敏感: 公开文档、系统状态信息

处理要求:
  - 高敏感: 必须加密存储，使用环境变量
  - 中敏感: 访问控制，定期审计
  - 低敏感: 基础访问控制
```

### 2. API安全要求
- **HTTPS强制**：所有API调用必须使用HTTPS
- **密钥管理**：使用安全的密钥生成和验证机制
- **访问控制**：实施基于角色的访问控制(RBAC)
- **审计日志**：记录所有安全相关操作

### 3. 网络安全
```yaml
要求:
  - 所有API调用必须使用HTTPS
  - 禁用不安全的HTTP连接
  - 使用有效的SSL证书
  - 定期更新证书
```

## 🌍 语言要求

- **优先级1**：匹配用户输入的语言
- **优先级2**：检查自定义指令中的语言要求

- **中文**：作为默认语言，适用于中文用户

## 📋 执行标准

### 1. 任务执行流程
1. **需求分析**：明确任务目标和约束条件
2. **方案设计**：基于规则制定执行方案
3. **实施执行**：严格按照规范执行任务
4. **质量验证**：验证结果是否符合要求
5. **文档记录**：记录执行过程和结果

### 2. 错误处理标准
- **错误识别**：及时识别和报告错误
- **错误分类**：按照严重程度分类处理
- **错误修复**：提供明确的修复方案
- **预防措施**：制定预防类似错误的措施

### 3. 性能标准
- **响应时间**：合理的响应时间要求
- **资源使用**：优化CPU、内存、网络使用
- **并发处理**：支持合理的并发请求
- **扩展性**：考虑系统扩展需求
