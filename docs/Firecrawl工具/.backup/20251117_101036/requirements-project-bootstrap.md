# 项目初始化需求说明

## 需求背景

- 当前仓库整合 Firecrawl 采集、火鸟门户发布与 n8n 自动化，需启动新一轮迭代前完成规范化初始化。
- 上一批次文档与代码较为分散，缺少统一的需求对齐与验收标准记录，影响后续的 Architect、Atomize 阶段执行。

## 项目目标

- 梳理本次迭代涉及的业务范围、输入输出与关键依赖，确保各团队对齐。
- 建立可复用的初始化基线，包括文档核查、环境检查与任务拆分前置条件。
- 输出明确、可测试的验收标准，为后续设计、开发与评估提供依据。

## 范围界定

### 包含内容

- 核查并补齐 5S/6A 要求的基础文档（说明文档、REQUIREMENTS/DESIGN/TASK/FINAL 等）。
- 盘点 Firecrawl 与火鸟门户相关配置（API Key、速率限制、MCP 工具可用性）。
- 校验本地开发环境的核心工具链（uv、pytest、ruff、mypy、pnpm 等）。
- 识别关键参考资料与现有代码模块的依赖关系。

### 不包含内容

- 不直接修改业务逻辑代码或 n8n 工作流。
- 不触达生产环境或运行长时间外部 API 调用。
- 不处理非本迭代范围的历史遗留问题，需在后续阶段排期。

## 关键输入输出

- 输入：现有文档与配置、API 凭据、仓库既有模块说明。
- 输出：对齐完成记录（本文件）、待补充文档清单、环境核查结果、后续设计阶段所需的信息汇总。

## 验收标准

- ✅ 文档核查：列出已存在与缺失的 5S/6A 关键文档，并确定补齐计划。
- ✅ 环境校验：验证核心命令可执行或给出修复指引，包含 Python 与 Node.js 工具链。
- ✅ 依赖梳理：明确 Firecrawl、火鸟门户、NewsAPI 等外部服务状态与速率限制配置。
- ✅ 风险登记：至少识别 3 类潜在风险并给出缓解措施。
- ✅ 交付记录：在项目说明文档中登记执行结果与下一阶段计划。

## 风险与应对

- **凭据过期**：集中校验 `.env` 或密钥管理配置，若缺失则安排替换流程。
- **工具链版本不一致**：记录当前版本，必要时使用 `uv` 或 `pnpm` 进行统一。
- **文档缺失导致沟通失效**：即时补齐或在 TASK 阶段排定优先级。

## 依赖与资源

- 代码：`Firecrawl工具/代码模块/*`、`n8n工具/文档/项目规则.md`、`AGENTS.md`。
- 资料：`docs/` 目录下的规范与快速参考、Firecrawl 官方资料子目录。
- 工具：已配置的 MCP 服务器（Firecrawl、GitHub、Filesystem、Playwright 等）。

## 后续动作

- Architect 阶段：基于核查结果更新或创建 `DESIGN_项目初始化.md`，补充架构图与数据流。
- Atomize 阶段：将待办拆分为可测的任务单元，生成 `TASK_项目初始化.md`。
- Approve 及后续阶段：按验收标准推进并在完成后更新 `说明文档.md` 与 `FINAL_项目初始化.md`。
