## 🎯 推荐执行方案

### 方案选择

经过分析，推荐以下方案：

#### 代码目录合并方案（推荐：方案 B - 渐进式）

**不立即合并，而是统一引用**：
- 保留 `code/` 和 `代码模块/` 两个目录
- 在 `代码模块/` 中创建 `core/` 子目录，软链接或复制 `code/` 的内容
- 统一文档中的引用，明确两个目录的用途
- 未来逐步迁移

**理由**:
- `code/` 只有 2 个基础工具文件，功能明确
- `代码模块/` 有 7 个业务模块文件，功能完整
- 立即合并风险较大，可能影响现有代码
- 渐进式迁移更安全

#### 文档目录合并（已完成 ✅）
- ✅ `文档/n8n与Firecrawl集成指南.md` → `docs/guides/n8n-integration-guide.md`
- ✅ 删除空的 `文档/` 目录
- ✅ 更新 README.md 中的链接

## ⚠️ 风险控制

### 高风险操作
1. **代码目录合并**: 可能影响现有代码和测试
2. **导入路径更改**: 需要全面测试

### 安全措施
1. **创建完整备份**: 在执行前创建备份
2. **分步执行**: 不要一次性执行所有操作
3. **测试验证**: 每步完成后进行测试
4. **Git 提交**: 每步完成后提交到 Git
