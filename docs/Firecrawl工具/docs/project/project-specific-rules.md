## 🎯 项目特定核心原则

### 1. N8N工作流优先原则
- **工作流优先** - 优先使用N8N工作流解决自动化需求
- **节点复用** - 充分利用现有节点，避免重复开发
- **模板化设计** - 创建可复用的工作流模板
- **版本管理** - 严格管理工作流版本和变更

### 2. 自动化优先原则
- **全自动化** - 追求端到端的全自动化解决方案
- **智能监控** - 实现智能化的监控和告警机制
- **自愈能力** - 具备自动故障检测和恢复能力
- **性能优化** - 持续优化工作流性能和资源使用

## 🔧 N8N特定开发规范

### 1. 工作流设计规范

#### 工作流命名规范
```yaml
命名格式: "[环境]-[业务域]-[功能描述]-[版本]"
示例:
  - "PROD-CRM-客户数据同步-v1.0"
  - "DEV-EMAIL-营销邮件发送-v2.1"
  - "TEST-API-数据清洗-v1.5"

环境标识:
  - PROD: 生产环境
  - DEV: 开发环境
  - TEST: 测试环境
  - STAGE: 预发布环境
```

#### 节点配置规范
```yaml
节点命名:
  格式: "[节点类型]-[具体功能]"
  示例: "HTTP-获取用户数据", "SET-数据转换", "IF-条件判断"

节点描述:
  必填字段: 每个节点必须填写描述信息
  描述内容: 说明节点的具体功能和处理逻辑
  更新要求: 节点功能变更时同步更新描述
```

#### 工作流文档化要求
```yaml
工作流描述:
  - 业务背景和目标
  - 数据流向和处理逻辑
  - 触发条件和执行频率
  - 错误处理策略
  - 监控和告警配置

节点文档:
  - 输入数据格式
  - 处理逻辑说明
  - 输出数据格式
  - 错误处理方式
```

### 2. MCP工具与N8N集成规范

#### N8N MCP工具优先级
```yaml
核心工具:
  1. mcp_n8n (N8N官方MCP工具)
     - 节点管理和配置

     - 执行状态监控

  2. firecrawl (网页抓取)
```

#### N8N节点选择策略
```yaml
节点选择优先级:
  1. 官方核心节点 (n8n-nodes-base)
  2. 官方AI节点 (@n8n/n8n-nodes-langchain)
  3. 社区验证节点 (GitHub Stars > 100)
  4. 自定义节点 (仅在必要时)

评估标准:
  - 功能匹配度 ≥ 90%
  - 社区活跃度 (最近6个月有更新)
  - 文档完整性 (有完整使用说明)
  - 安全性验证 (无已知安全漏洞)
```

### 3. 数据处理规范

#### 数据格式标准化
```yaml
输入数据格式:
  - JSON格式优先
  - 字段命名使用camelCase
  - 必填字段明确标识
  - 数据类型严格定义

输出数据格式:
  - 保持格式一致性
  - 包含处理状态信息
  - 错误信息结构化
  - 时间戳标准化 (ISO 8601)
```

#### 数据验证要求
```javascript
// 数据验证示例
const validateUserData = (data) => {
  const required = ['userId', 'email', 'name'];
  const missing = required.filter(field => !data[field]);
  
  if (missing.length > 0) {
    throw new Error(`缺少必填字段: ${missing.join(', ')}`);
  }
  
  // 邮箱格式验证
  const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
  if (!emailRegex.test(data.email)) {
    throw new Error('邮箱格式不正确');
  }
  
  return true;
};
```

## 🔒 N8N项目安全规范

### 1. 凭据管理
```yaml
凭据存储:
  - 使用N8N内置凭据管理系统
  - 敏感信息不得硬编码在工作流中
  - 定期轮换API密钥和访问令牌
  - 使用环境变量管理配置信息

凭据分类:
  高敏感: 数据库密码、API密钥、OAuth令牌
  中敏感: 服务器地址、用户名、配置参数
  低敏感: 公开API端点、文档链接
```

### 2. 网络安全配置
```yaml
网络访问控制:
  - 限制N8N实例的网络访问范围
  - 使用HTTPS进行所有外部通信
  - 配置防火墙规则限制不必要连接
  - 定期更新SSL证书

API安全:
  - 所有API调用使用认证机制
  - 实施请求频率限制
  - 记录所有API访问日志
  - 定期审查API权限
```

### 3. 数据安全处理
```yaml
敏感数据处理:
  - 个人身份信息(PII)必须加密传输
  - 支付信息遵循PCI DSS标准
  - 医疗数据遵循HIPAA规范
  - 日志中敏感信息脱敏处理

数据备份:
  - 工作流配置定期备份
  - 执行历史数据保留策略
  - 备份数据加密存储
  - 定期测试数据恢复流程
```

```javascript
// N8N工作流测试用例
describe('用户数据同步工作流', () => {
  test('正常数据处理流程', async () => {
    const inputData = {
      userId: '12345',
      name: '张三',
      email: 'zhangsan@example.com'
    };
    
    const result = await executeWorkflow('用户数据同步', inputData);
    
    expect(result.success).toBe(true);
    expect(result.data.userId).toBe('12345');
    expect(result.data.syncStatus).toBe('completed');
  });
  
  test('异常数据处理', async () => {
    const invalidData = {
      userId: '',
      name: '张三'
      // 缺少email字段
    };
    
    const result = await executeWorkflow('用户数据同步', invalidData);
    
    expect(result.success).toBe(false);
    expect(result.error).toContain('缺少必填字段');
  });
});
```
